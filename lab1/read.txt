🌋 Нам нужен Vulkan!

Для разработки на Vulkan нам нужно скачать SDK: набор инструментов, заголовочных файлов и библитек.

Его можно скачать отсюда: https://vulkan.lunarg.com/sdk/home

Сам сайт lunarg.com не работает в России без прокси, но прямые ссылки на скачивание работают.

В итоге нам нужны заголовки Vulkan (VulkanHeaders), библиотека vulkan-1.lib или vulkan-1.a/so для пользования функциями Vulkan без специального загрузчика и компилятор шейдерных языков GLSL -- glslc.

Проверьте после установки Vulkan SDK, что glslc находится в PATH и доступен из терминала.

Для юзеров Windows сразу ссылка на установщик: https://sdk.lunarg.com/sdk/download/1.4.321.1/windows/vulkansdk-windows-X64-1.4.321.1.exe

Для юзеров Ubuntu достаточно установить данные пакеты: libvulkan-dev и vulkan-validationlayers

Для других дистрибутивов Linux -- ищите в вики дистрибутива или форумах.

Для юзеров macOS нужно скачать пакет: https://sdk.lunarg.com/sdk/download/1.4.321.0/mac/vulkansdk-macos-1.4.321.0.zip
Далее установить его, как в этом гайде: https://gist.github.com/Resparing/d30634fcd533ec5b3235791b21265850

DISCLAIMER: Я никогда не пользовался macOS, поэтому те, кто будут устанавливать и сделают это успешно -- поделитесь своим опытом и помогите коллегам!

В стартовом репозитории вы будете писать код внутри application.cpp

Функции initialize и shutdown нужны для создания и уничтожения объектов Vulkan. (все функции vkCreate* имеют противоположный vkDestroy*, поэтому не забывайте уничтожать все объекты, иначе получите ошибки валидации)

Говоря про валидацию: она включена и любые попытки что-то сделать не так с точки зрения спецификации Vulkan будут логированы в консоль, где можно посмотреть, с чем произошёл косяк.

В функции update вы будете писать код интерфейса с помощью библиотеки ImGUI, а также обновлять (буквально update) динамические данные в вашей программе, например матрицы.

Кстати про ImGUI, я рекомендую посмотреть на возможности ImGUI после того, как скомпилируйте проект стартового кода. Там будет демо окно, где показаны все возможные элементы интерфейса. В файле imgui_demo.cpp этой библиотеки описана реализация этой демки и оттуда можно узнать, как у себя реализовать элементы интерфейса.

В функции render вы будете рисовать, а именно записывать команды в буфер, который вам дают из аргумента функции FrameData. Т.е. все функции vkCmd* вы будете писать там.

Все самые важные объекты для работы с Vulkan API (VkDevice, VkExtent2D swapchain_extent (размер окна), VmaAllocator, VkRenderpass, VkQueue и др.) находятся в глобальной структуре, к которой можно получить доступ через graphics::internal::context . Рекомендую ознакомиться с написанным стартовым кодом, минимально можно глянуть заголовочные файлы, если боитесь смотреть на реализацию.




Также рекомендую взглянуть на CMakeLists.txt, там написан код для компиляции шейдеров и пример, как включить компиляцию.

Будте готовы изменять этот файл, потому что вы в любом случае будете добавлять позже библиотеки для чтения изоражений, 3D моделей и какую-нибудь библиотеку для линейной алгебры.

Чтобы не гадать, как расположить поля в uniform структурах, можно воспользоваться вот этим инструментом.

https://jackjamison.net/interactive/glsl-layout-calculator/

Выбираете стандарт выравнивания (std140 для uniform или std430 для storage), вставляете поля стурктур GLSL в левое окно, а в правом получаете байтовые отрезки этих полей. Где написано IMPLICIT PADDING, туда нужно добавить незначащих байтов для корректного выраванивания полей.

Добавлять байты выравнивания нужно именно в структурах в C или C++ коде, а не в GLSL коде. Т.е. вы будете подгонять выраванивание данных под то, что ожидает увидеть видеокарта в коде на GLSL.
